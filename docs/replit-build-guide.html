Start here

What you are doing

The application already exists and works on your computer. You are moving a copy of it onto Replit — a website that runs code for you — so it is reachable from a browser. Nothing needs to be built or written. The work is packaging, uploading, and configuring.

What you need before you start

  • The project on your computer at c:\\InventDB Legal.
  • An InventDB address — it looks like https://something.sandbox.inventdb.com. This is where the data lives. The app is useless without it.
  • A username and password for that InventDB. These are what you will log into the app with. The app has no separate sign-up.
  • Git installed on your computer. If you are unsure, step 01 will tell you.
Read once

Do the steps in order, and do not skip the checks. Each step has three parts: what to do, what you should see afterwards, and what to do if you see something else. The middle part is the important one — almost every way this goes wrong is somebody carrying on past a step that silently didn't work.

—

Words you'll need

Five terms. You will meet all of them in the next twenty minutes.

Repl

One project on Replit. A folder of files plus a computer to run them on. You will create exactly one.

The Agent

Replit's AI assistant, in a chat panel. You will paste three messages to it. It does the technical work; you check its results.

The Shell

A black box where you type commands. Replit has one built in. You will use it twice, and only to check things.

Secrets

Replit's safe place for passwords and addresses. Things put here are not visible in your files and don't get copied if someone forks your project.

Webview

A small browser inside Replit showing your running app. This is where you will see the login page.

Note

Replit changes its layout from time to time. If a button isn't quite where this guide says, look for the same word — the names are stable even when the positions move. Nothing here depends on a button being in an exact corner.

Part 1 of 4

On your computer5 min

Turn the project into a single zip file on your Desktop. Replit never sees your computer, so this is how the code gets there.

01

Check nothing's missing

The zip is made from your last saved version, not from what's on screen. This checks they're the same.

Do this
  1. Press Windows key + S and type powershell.
  2. Click Windows PowerShell. A blue window opens.
  3. Copy the command below, right-click inside the blue window to paste, press Enter.
You'll see

Either nothing at all, or a list of file names. Nothing at all is what you want.

If not

A list of files means you have unsaved changes, and they will not be in the zip. Save them first (in your editor: commit them), then run this again until it prints nothing.

git : The term 'git' is not recognized means Git isn't installed. Install it from git-scm.com, close PowerShell, and start this step again.

Paste into PowerShell
cd "c:\\InventDB Legal"
git status --porcelain
02

Make the zip

One command. It puts a file on your Desktop.

Paste into the same PowerShell window
$out = "$([Environment]::GetFolderPath('Desktop'))\\inventdb-legal-source.zip"
git archive --format=zip -o $out HEAD -- . ':(exclude)CA_Litigation_Practice_Dataset.xlsx'
Get-Item $out | Select-Object Name, Length
Do this

Paste it, press Enter, then look at your Desktop.

You'll see

A table with inventdb-legal-source.zip and a Length of roughly 850000. And the file on your Desktop.

If not

Length is 0 — the command failed. Delete the file from your Desktop and run it again. Do not upload a zero-byte zip; it will look like it worked and then fail confusingly three steps later.

Why

You could zip the folder by hand, but don't. This command includes only the real project files — about 280 of them. Zipping by hand would sweep in several hundred megabytes of downloaded libraries, and possibly a password file.

Set up Replit5 min

03

Make an account

Do this
  1. Go to replit.com.
  2. Sign up, or log in if you already have an account.
You'll see

A home screen with a Create or + button.

Worth knowing

On a free account, projects may be public — anyone can read and copy your files. That is a setting, and step 13 explains what it does and doesn't expose. If that matters to you, check it now rather than later.

04

Create an empty project

Do this
  1. Click Create.
  2. Choose Blank Repl — not a Python template, not a React template.
  3. Name it inventdb-legal.
  4. Click Create.
You'll see

An editor with three areas: a file list on the left, a big editing area, and a chat panel (the Agent). The file list will be nearly empty.

If not

If you see files like main.py or a src folder, you picked a template. Delete the Repl and create a Blank one. Merging your app into a template is the single most common way this goes wrong.

05

You'll see

A short reply confirming Python and Node are enabled, telling you the folder path, and saying it is waiting. It should not have created any files.

You'll see

inventdb-legal-source.zip in the file list.

If not

If clicking the zip opens a window of gibberish saying "binary", that is fine and expected — close the tab. Replit is trying to show you a zip as if it were text.

Important

Upload the single zip file. Do not unzip it on your computer and drag 280 loose files in — browser uploads of large folders drop files silently, and you won't know which ones are missing.

08

Add the connection

Tell the app which InventDB to talk to. You do this yourself — don't ask the Agent.

Do this
  1. Find Secrets in the left sidebar (it may be under Tools). The icon is a padlock.
  2. Click New secret.
  3. Key: INVENTDB_BASE_URL
  4. Value: your address, e.g. https://abc123.sandbox.inventdb.com
  5. Save.
You'll see

One secret listed, named INVENTDB_BASE_URL.

Careful

No slash on the end. https://abc123.sandbox.inventdb.com/ with a trailing slash is the most common cause of "can't log in" later. No /api on the end either — just the address.

Set it up

Do this

Message 3 of 3 · paste to the Agent
I have uploaded a COMPLETE, WORKING application — InventDB Legal, a legal
practice management system. It is finished, tested and correct. Do NOT rebuild,
rewrite, scaffold, modernise, or create a second version of it. Read the code
before you touch anything.

_scaffold/ holds the starter files you generated earlier. Do not read from it,
merge it, or restore anything out of it. The real application is backend/ and
frontend/.

READ THIS FIRST — three of your defaults are wrong here and will break it:
  - The backend is Flask, NOT FastAPI. Do not convert it.
  - The frontend is React 18 + Vite, NOT Create React App and NOT Next.js. The
    env var is VITE_API_BASE and it is already correct at its default of "/api".
  - There is NO DATABASE. Not Postgres, not MongoDB, not SQLite, not Replit DB.
    Do not add one, do not add an ORM, migrations, a users table or a session
    store. ALL data AND ALL authentication live in InventDB's REST API. The
    backend forwards the caller's bearer token and holds nothing of its own.

The Flask app already serves frontend/dist as the SPA when that folder exists,
so this deploys as ONE service on ONE port. Do not split it into two services
and do not add a reverse proxy.

Your only job is to make it run here:

1. pip install -r backend/requirements.txt, and `npm ci` in frontend/.
2. Build the SPA:  cd frontend && npm run build     (produces frontend/dist)
3. Set the run command, started from backend/:
      gunicorn -w 2 --worker-class gthread --threads 8 --timeout 0 \
               -b 0.0.0.0:${PORT:-5000} wsgi:app
   --timeout 0 and threaded workers are REQUIRED. /api/analyze/chat/stream and
   /api/reports/templates/<id>/edit/stream are long-lived Server-Sent Events
   relays that idle for minutes between chunks while the agent reasons. Default
   sync workers kill them mid-stream and the Analyze room looks broken.
4. Map port 5000 to the external web port in .replit.
5. Configuration comes from Replit Secrets. INVENTDB_BASE_URL is the only one
   that must be set. backend/.env.example lists the rest and their defaults —
   read it, do not create a .env, and do not invent new variables.

Note on ports: backend/app/config.py defaults API_PORT to 8010 and the Vite dev
server to 5174. Those defaults keep this app off the ports a sibling InventDB
app uses locally; they do not apply here, because gunicorn is given -b
explicitly. Do not "correct" them, and leave _refuse_occupied_port in
backend/app/main.py alone — it guards the dev entrypoint and never runs under
gunicorn.

Verify before reporting done, and paste the ACTUAL output:
      curl -s localhost:5000/api/health
      curl -s localhost:5000/

Constraints:
- Do NOT modify anything under backend/app/, frontend/src/, backend/tests/,
  frontend/e2e/ or contract/. If something fails, fix the environment
  configuration, not the application code.
- Keep the backend pure-Python. Do not add FastAPI, pydantic, or anything
  needing a C or Rust toolchain.
- Do not install Playwright browsers unless I ask.

Report exactly which files you changed.

Log in

Do this

Type your InventDB username and password into the login page and sign in.

You'll see

A dashboard with real numbers, and a list of sections down the left: Matters, Clients, Timekeepers, Time Entries, Invoices, Trust Ledger and the rest. That is the finished application. You're done.

If not

"Invalid username or password" — the app reached InventDB and it said no. Check your credentials.

A network or connection error — the app couldn't reach InventDB at all. Go back to step 08: the address is wrong, or has a slash on the end.

Empty lists everywhere — you connected to an InventDB that has no data in it yet. That is not a fault in the app.

Optional: prove it's identical

"It loads" and "it is the same application" are different claims. The project carries its own tests; running them settles it. Skip this if you just wanted it online.

Replit Shell · takes about 10 minutes
pip install -r backend/requirements-dev.txt
cd backend  && python -m pytest
cd ../frontend && npm run typecheck && npm run typecheck:e2e
npx playwright install chromium
npx playwright test --workers=2
What runsA correct build says
Backend tests1176 passed, 6 xfailed
Type checks (twice)no errors
Browser tests560 passed
Two things

Keep --workers=2. Without it the browser tests use more memory than the container has and get killed part-way, which looks exactly like a failure but isn't one.

6 "xfailed" is correct. Those are known, documented gaps that are deliberately marked. If you ever see 1182 passed and 0 xfailed, someone changed something they shouldn't have.

13

Optional: put it online

Right now the app runs only while your Repl is open. Deploying gives it a permanent address.

Click Deploy and follow the prompts. Two things are worth understanding before you do, because people mix them up:

Visitors getCan they see your code?
DeployingThe running app at a web addressNo. No file list, no copy button
A public ReplYour whole projectYes — readable and copyable in one click

These are separate settings. You can deploy a private project. Pressing Deploy does not make your code public, and making your Repl public is not how you deploy.

Worth knowing

Two things are visible to anyone who can reach a deployed app, whatever you choose: the part of the app that runs in the browser, and the address of the InventDB it talks to. Neither is dangerous here — the app stores no password of its own, so a copy of it is an empty shell until someone can log in — but decide knowingly rather than discovering it later.

If the Agent asks

You don't need to understand these. But if the Agent offers to "fix", "clean up" or "modernise" any of them, the answer is no — each one is deliberate and was got wrong at least once already.

  1. Don't sort the JSON keys. Their order is the column order of every table in the app.
  2. Don't buffer the streaming endpoints. They must be passed through untouched, or the AI features stop mid-answer.
  3. Don't load files into memory to serve them. Downloads and previews stream deliberately.
  4. Don't move the dropdown colours onto the parent control. The operating system draws those menus and ignores it.
  5. Don't rewrite the dashboard queries to filter instead of group. The database has a quirk where the "obvious" version silently returns one wrong number.
  6. Don't move the totals into the app. The database returns at most 1000 rows, so adding up in the app would total the first page and report it as the whole.
  7. Don't move the import into the page. It lives outside on purpose: otherwise clicking to another screen mid-import stops it halfway and says nothing.
  8. Reports and AI conversations are shared across apps on the same InventDB. That's how InventDB works, not a bug here.
