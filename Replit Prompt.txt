================================================================================
LOAD-BEARING ODDITIES — do not "clean these up"
Every one of these was found the hard way. They look wrong and are not.
================================================================================

1. Flask must NOT sort JSON keys (app.json.sort_keys = False). Row key order IS
   column order through a thin proxy; sorting them reorders every table.

2. The SSE endpoints set X-Accel-Buffering: no and must never be buffered, parsed,
   reformatted or accumulated. Relay them untouched.

3. File download / preview / thumbnail STREAM bytes. Never buffer a file into
   memory.

4. Select-option colours are set on the <option> elements, not the parent control.
   The OS draws select menus and ignores the parent's styles.

5. InventDB's SQL engine collapses a GROUP BY to a single row when the WHERE
   clause contains a function call. backend/app/routers/dashboard.py and
   reports.py therefore GROUP BY a column instead of filtering on it — e.g. the
   cash-flow split groups on `deposited_to` rather than using
   `WHERE lower(deposited_to) = '...'`. Rewriting those into the "obvious" filtered
   form silently returns one row holding the grand total. Tests pin this.

6. InventDB caps a statement at 1000 rows. Every dashboard figure is therefore a
   SUM/COUNT/GROUP BY executed inside InventDB, and free-text search is an OR of
   LIKEs run upstream — not a Python rollup over a page of results. With 34,000
   time entries, a Python sum over `SELECT *` would report the total of the first
   page. Do not "simplify" these into client-side aggregation.

7. frontend/src/pages/importRun.ts holds the running import in a module-level
   store, deliberately OUTSIDE React. Moving it into component state re-introduces
   a data-loss bug: navigating away unmounts the page, aborts the batches
   mid-flight, and leaves half the rows written with nothing on screen to say so.
   frontend/e2e/import-navigation.spec.ts guards this.

8. Reports templates and Analyze threads live in InventDB's _System namespace, at
   the instance level — they are shared with SOAR and with any sibling app on the
   same instance. That is upstream behaviour, not a bug in this app.
